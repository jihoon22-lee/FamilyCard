# ADR 0019 — 실적 추정 규칙·기간·수동 판단과 기록

- 상태: 채택
- 날짜: 2026-09-25

## 결정

실적 규칙은 카드 소유권을 검사한 뒤 버전을 증가시키고 설정·공식 조건 출처·유효 기간을
`BenefitRuleRevision`에 보존한다. 결제일도 버전에 저장해 카드 설정 변경이 과거 사이클을
조용히 바꾸지 않게 한다. 구간/최소 금액은 정수이고 공식 조건 HTTPS 주소와 사용자 확인이
필요하다. 주소 내용의 자동 검증이나 특정 상품 조건의 추측 등록은 하지 않는다.

산정 기간 시작일에 적용 가능한 최신 버전을 사용한다. 종료일이 있으면 전체 사이클을
포함해야 한다. 공식 출처가 없는 legacy 설정은 보존하지만 자동으로 추정치를 표시하지
않는다. 실제 카드사와의 한 사이클 대조는 별도의 최종 검증이다.

- 원결제 사이클 정책: 확정 승인 `netAmount`를 산정한다.
- 취소 사이클 정책: 승인 `netAmount + canceledAmount`에서 해당 사이클의 연결된 취소만
  차감한다. 원승인 당시 규칙을 확인할 수 없으면 불확실로 표시하고 임의 차감하지 않는다.
- 최소 금액은 원결제 정책에서는 취소 반영 순액, 취소 사이클 정책에서는 원승인액 기준이다.
  이 모델에 맞지 않는 상품은 지원 범위를 확장하기 전 공식 수치와 일치한다고 보지 않는다.
- 원거래 없는 취소는 설계 05에 따라 취소 사이클에서 차감하되 원거래/제외 적격성을 모르는
  **불확실 추정**으로 표시한다. 단순 월 순사용액 화면은 계속 원거래 확인 대상으로 분리한다.
- 카드 미지정·검토 상태·원화 미확정 거래는 실적에 임의 포함하지 않는다.

카테고리 이름/제외 코드는 가족 공용이며 관리자 웹만 편집한다. 가맹점 학습은 **소유자별
정확한 이름 일치**만 지원한다. 다른 구성원에게 전파하지 않고 수동 분류를 덮어쓰지 않는다.
가맹점명 휴리스틱은 사용자 선택 제외 항목에만 적용하며 사유를 표시한다.

실적 포함/제외 수동 판단은 `benefitOverride`로 파싱의 `isManuallyEdited`와 분리한다.
승인 원거래에 적용하며 취소 자체를 임의 포함/제외해서 순액과 모순시키지 않는다.
조회는 계산 결과와 사유를 표시하고, 사용자가 기록을 누르면 하나의 SERIALIZABLE
트랜잭션에서 추정 결과 snapshot과 거래의 최신 기록 사유 `excludeReason`을 저장한다.
과거 snapshot을 갱신/삭제하지 않는다. 최신 사유 하나만으로 과거 산정을 재현하지 않으며
snapshot의 기간·규칙 버전·거래별 기여액을 함께 본다.

## 검증과 한계

가공 표본으로 경계 -1원/정확 경계·세금/상품권·수동 포함/제외·부분/전액 취소·양쪽 취소
정책·원거래 불확실·KST 자정·윤년/월말·결제일 버전 고정을 검증한다. 격리 DB에서 타인
카드/분류 변경 차단, 소유자별 학습, 과거 버전/기록/원문 보존을 확인한다.

최종 성능 검증에서 전체 카드 장부 조회를 산정 기간과 필요한 연결 원거래만 읽도록 줄였다.
산정 기간 거래 10,000건 상한을 넘으면 부분 합계를 전체 추정치로 표시하지 않고 중단한다.
혜택 월 한도는 조건 설명용이며 실제 혜택 사용액을 수집하지 않아 한도 기반 추천은 하지 않는다.

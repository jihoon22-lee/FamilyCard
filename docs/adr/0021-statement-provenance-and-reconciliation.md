# ADR 0021 — 명세서 파일·행 보존과 검토 후 보정

- 상태: 채택
- 날짜: 2026-09-25

## 결정

CSV/XLSX 원본 바이트는 `StatementImport.originalFile`, 소유자별 파일 해시는 중복 업로드
키로 보관한다. 각 행은 `RawMessage(source=STATEMENT, originKind=STATEMENT_UPLOAD)`로
파일 ID·행 위치·열 이름/셀 값과 함께 저장한다. 가짜 기기를 만들지 않고 ownerMemberId를
사용한다. 알림 파서는 명세서를 재해석하지 않으며 컬럼 매핑은 별도 경로에서 처리한다.

한 파일은 한 카드의 원화 내역이다. 날짜/금액/가맹점/거래 종류·승인액/순액/청구액의 의미와
조회 기간을 사용자가 선택한다. 인코딩은 UTF-8/EUC-KR, XLSX는 첫 시트를 지원한다.
잘못된 행도 원문으로 보존하고 미확정으로 표시한다. 같은 파일의 매핑 수정은 미연결 행만
재해석하며 연결한 근거와 수동 제외를 보존한다. 이전 매핑은 감사 이력에 남긴다.

후보는 같은 소유자·카드·종류, 정확 가맹점(공백/대소문자 무시), 날짜 ±3일을 사용한다.
기간 차이는 매입/청구 시점 때문에 허용하지만 **자동 거래 확정은 하지 않는다**. 사용자가
검토한 뒤 유일한 일치 후보에 일괄 연결하거나, 별도 누락 승인/취소를 생성하거나, 특정
거래의 승인/취소 금액을 보정한다. 여러 후보는 직접 선택한다.

순액/청구액은 비교·근거 연결용이다. 이를 원승인 금액으로 덮어쓰거나 새로운 승인으로
만들지 않는다. 취소액이 원승인보다 커지는 보정도 거부한다. 일괄 작업은 한 트랜잭션으로
처리하고 오류가 있으면 전체 롤백한다. 판단은 `ReviewDecision`, 근거는 수동 evidence로
남겨 자동 재처리가 덮어쓰지 않게 한다. 원문과 파일은 수정/삭제하지 않는다.

명세서에 연결되지 않은 기존 거래는 검토 신호일 뿐이다. 명세서에서 안 보인다는 이유로
삭제·취소 처리하지 않는다. 연결 전에는 정상 거래도 미연결 목록에 포함될 수 있다.

## 자원·입력 경계

파일 2MiB, 데이터 1,000행/50열, 셀 2,000자, 대사 거래 10,000건 상한을 둔다.
XLSX는 압축을 순차 검증하고 총 해제 20MiB/개별 XML 2MiB/파일 10MiB/200개 엔트리,
XML 행·셀 수와 희소 행 번호를 먼저 검사한다. DTD/엔티티와 수식 셀은 거부한다.
원본 다운로드는 세션·소유권을 다시 검사하고 attachment/no-store로 응답한다.

- [ExcelJS](https://github.com/exceljs/exceljs): XLSX 값 읽기, 수식 객체는 실행/사용하지 않음.
- [yauzl](https://github.com/thejoshwolfe/yauzl): lazy entry/validateEntrySizes와 실제 해제 바이트 제한.
- [csv-parse](https://csv.js.org/parse/options/max_record_size/): CSV quoting과 레코드 크기 제한.

## 검증

가공 CSV/XLSX·잘못된 날짜·압축 큰 XML·희소 행·수식·건수 한도, 원본/원문 불변,
중복 업로드·미연결 매핑 수정·다른 소유자 접근 거부·일괄 오류 롤백·금액 보정·알림 재처리
독립성을 격리 DB에서 검증한다. 실제 카드사 명세서 정답과의 대조는 최종 검증으로 남긴다.

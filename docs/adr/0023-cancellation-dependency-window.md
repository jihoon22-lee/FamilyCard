# ADR 0023 — 취소 후보 의존성이 닫힌 창에서 재투영

- 상태: 채택 (2026-09-26)
- 관련: 리뷰 후속 R01, ADR 0016

## 결정

고정 날짜 범위나 기존 canceledAmount를 고정 잔여액으로 주입하는 방식 대신, 변경 전·후
거래를 시작점으로 승인/취소 후보의 연결 성분을 확장합니다. 창은 연속 날짜 구간이 아니라
서로 영향을 주는 거래 집합입니다. 기존 전체 projectCancellations를 기준 구현으로 유지합니다.

같은 구성원·카드·통화에서 취소의 유효 경계(시각 또는 DAY의 KST 끝)보다 앞선 60일 안
승인은 모두 의존 후보입니다. 낮은 점수 후보도 차점자와의 점수 차이에 영향을 주므로 제외하지
않습니다. 기존 canceledTxId 연결은 날짜 조건과 무관하게 포함해 변경 전 연결도 정리합니다.
변경 전·후의 시각/카드/종류/연결을 모두 시작점으로 넣으며, 카드 이동은 양쪽 카드를 재계산합니다.

새 후보가 없을 때까지 양방향 확장합니다. 창 밖 거래는 창 안 승인 잔여액을 소비할 수 없고,
창 안 취소의 후보 순위에도 영향을 줄 수 없습니다. 따라서 동일한 수동 우선/시간/ID 순서로
창을 처음부터 계산하면 전체 재계산과 동일합니다. 수동 연결과 날짜 경계도 같은 규칙을 씁니다.

DB 조회는 최대 100개 시작점을 묶어 범위/기존 연결을 조회하고 이미 읽은 ID를 제외합니다.
카드 평생 거래 수에는 상한을 두지 않습니다. 연결 성분이 10,000건을 넘으면
PROJECTION_WINDOW_LIMIT로 트랜잭션 전체를 롤백합니다. 조용히 잘라 계산하거나 무제한
전체 재계산으로 전환하지 않습니다. 취소가 매우 조밀한 원장은 창이 전 이력으로 확장될 수
있다는 한계가 있습니다. canceledTxId 인덱스를 보존형 migration으로 추가합니다.

## 복구와 검증

관리자 WEB/FAMILY 전용 `/family/projection`은 기본 드라이런으로 전체 결과 차이 건수를
비교합니다. 명시적 반영 시 Serializable 트랜잭션과 감사 기록을 사용합니다. 별도 복구
상한 100,000건과 트랜잭션 시간 한도를 두며 일반 수집 경로는 이 도구를 호출하지 않습니다.

3,000개 결정적 무작위 가공 원장 변경으로 전체/창 투영 동등성을 확인합니다. 부분취소,
다중 취소, 수동 연결, DAY 정밀도, 시각/종류/상태 변경과 60일 연쇄를 포함합니다.
격리 DB의 단일 카드 과거 12,000건 + 신규 승인/취소/중복 원문 처리를 검증하고 조회 반환
행 수를 계측합니다. 실제 원문/거래 값은 테스트·문서에 포함하지 않습니다.

## 누적 회귀 재실행

기존 격리 13개월 승인 5,000 + 취소 500건에서 동일 63회 HTTP 요청/후보 재시작을
재실행했습니다. 반복 메모리 161~162MiB(이전 164~165), 최대 관측 179MiB(이전 218).
실적 warm 63~76ms(이전 86~100), XLSX 50~62ms(이전 78~81).
일부 다른 경로는 실행별 변동이 있습니다(예: PDF 404~477ms, 이전 413~414).
모든 요청의 시간이 줄었다고 단정하지 않습니다. 원문 기준선 955건 누락/변경 0,
재시작 후 세션/데이터 보존을 확인했습니다. 신규 처리 경로는 12,000건 카드의 반복
시나리오 전체에서 반환 거래 행 수 1,000 미만으로, 과거의 건당 전체 조회보다 작습니다.

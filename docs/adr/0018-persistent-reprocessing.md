# ADR 0018 — 범위 재처리의 지속 미리보기와 대상 고정

- 상태: 채택
- 날짜: 2026-09-25

## 결정

미리보기와 반영 예약을 `ReprocessingRun`으로 저장하고 20건씩 진행한다. 브라우저가
닫혀도 기존 Node 처리 주기가 이어간다. 자동 처리를 끈 검증 서버에서는 수동 진행도 가능하다.
작업 진행 위치·원문별 작업 생성은 하나의 SERIALIZABLE 트랜잭션에 묶는다. 프로세스가
중간에 종료되면 해당 배치는 롤백되고 이전 위치부터 재개한다. 동시 실행은 충돌 재시도한다.

미리보기에서 본 원문 ID는 `ReprocessingTarget`에 보존한다. 이후 상태 필터가 달라져도
반영은 정확히 이 집합을 사용한다. 반영 요청은 previewId unique로 중복 예약을 막는다.
작업은 생성 당시의 보이는 구성원 목록을 저장하고 매 배치에도 현재 scope를 재검사한다.
ADMIN 폰에서는 같은 사람의 FAMILY 작업을 조회하거나 적용할 수 없다.

활성 파서 규칙과 대상 카드/별칭의 해시를 비교한다. 설정이 달라지면 중단하고 새 미리보기를
요구한다. 수동 판단은 미리보기와 실제 적용 모두 건너뛴다. 악화 예상이 있으면 명시 확인이
필요하고, 실제 처리에 실패해도 기존 거래는 보존한다.

## 의미와 한계

미리보기의 복구/변경/악화는 파싱과 카드 연결 기준이다. 자동 중복 병합·취소 연결을
가상의 전체 장부에 적용하는 금융 시뮬레이션은 아니다. UI에서도 이 한계를 표시한다.
기존 승인 번호·원결제일 등 모든 대사 필드 변경은 실제 검토가 필요하다. 작업 중 다른
사람이 거래를 수동 수정하면 실제 적용에서는 최신 수동 판단을 우선한다.

카드사 필터는 이전에 식별된 카드사를 사용한다. 카드사를 아직 모르는 NO_RULE 원문은
카드사 필터 없이 처리한다. 모든 원문·대상·판단 이력을 보존하고 거래 삭제는 하지 않는다.
반영 DONE은 처리 작업 예약 완료이며 거래 확정 완료가 아니다. 실제 작업의 실패/대기는
검토 화면에서 확인한다. 설정 변경으로 일부 배치만 예약된 경우 이미 예약한 작업은
취소하지 않고, 새 설정으로 미리보기/재처리해 수렴시킨다.

## 검증

격리 DB에서 25건의 동시 두 배치, 중간 상태 변경 뒤 동일 25건 예약, 중복 반영 요청,
타인 작업 접근 거부, 설정 변경 중단, 악화 경고와 수동 보존을 확인한다. API는 세션과
same-origin을 확인하고 4KiB 본문 상한을 적용한다.

# ADR 0003 — 앱 대시보드를 네이티브가 아니라 WebView로

- **상태**: 채택
- **일자**: 2026-08-10

## 배경

[ADR 0002](0002-server-required.md)에서 서버가 필요하다는 결론이 났지만, 원래 요구 중 하나는 여전히 유효합니다.

> 가족 입장에서는 앱 아이콘 하나 눌러서 다 보고 싶다.

가족에게 "앱도 깔고, 브라우저 북마크도 해두고, 그때그때 골라 쓰세요"라고 하면 안 씁니다. 아이콘 하나여야 합니다.

동시에 [ADR 0002](0002-server-required.md)의 원칙이 있습니다.

> 자주 바뀌는 것은 전부 서버에 두고, APK는 한 번 깔면 다시 안 건드리게 만든다.

대시보드는 **가장 자주 바뀌는 부분**입니다. 화면을 고칠 때마다 가족 전원에게 재설치를 부탁할 수는 없습니다.

## 검토한 대안

### A. 네이티브 대시보드 (Compose) + 얇은 서버

앱이 화면을 그리고, 서버는 데이터만 API로 제공합니다.

**장점**: 앱 느낌이 가장 좋음. 오프라인에서도 마지막 데이터 열람 가능

**탈락 이유**
- 화면을 고칠 때마다 **APK 재배포 + 가족 전원 재설치**
- 실적 규칙 편집, 미확정 큐 교정 같은 폼 위주 관리 화면을 Compose로 만드는 비용이 큼
- PC 큰 화면에서 볼 수 없음 — 가족×카드 매트릭스는 넓은 화면이 훨씬 유리
- 결국 관리자용 웹 화면은 따로 만들어야 해서 **UI를 두 번 구현**하게 됨

### B. 앱과 웹 완전 분리 (앱은 수집만, 대시보드는 PWA)

앱은 설치 후 숨겨두고, 대시보드는 브라우저에서 PWA로 홈화면에 추가합니다.

**장점**: 구조가 가장 단순. WebView 연동 코드가 아예 없음

**탈락 이유**: 아이콘이 2개가 됩니다. 원래 요구를 만족하지 못합니다. (다만 구조적으로는 아래 C와 거의 같아서, C의 WebView 연동이 문제를 일으키면 언제든 이쪽으로 후퇴할 수 있습니다.)

### C. 앱 하나 + WebView 대시보드 ← **채택**

앱 안에 하단 탭 2개를 둡니다.

- **대시보드 탭** — `WebView`로 서버 UI를 로드
- **설정 탭** — Compose 네이티브 (서버 주소·토큰·권한 상태·전송 로그)

## 결정

**C를 채택합니다.**

가족이 보는 것은 앱 아이콘 하나지만, 대시보드는 실제로 서버가 그린 화면입니다. 그래서:

- **화면을 고쳐도 APK 재배포 불필요** — `docker compose up -d` 한 번
- **UI를 한 번만 구현** — 같은 화면이 앱에서도 PC 브라우저에서도 동작
- PC에서 큰 화면으로 보고 싶으면 같은 주소에 접속하면 됨

설정 탭만 네이티브인 이유는, 권한 상태 조회와 시스템 설정 화면 이동은 WebView가 할 수 없기 때문입니다.

## 결과

### 웹 UI는 모바일 우선으로 만든다

주 사용처가 폰 화면 안의 WebView입니다. PC는 보조입니다. 반응형 브레이크포인트를 그 순서로 잡습니다.

### 로그인 화면을 안 보여주기 위한 세션 교환이 필요하다

WebView를 열 때마다 로그인하라고 하면 앱이 아닙니다. 디바이스 토큰을 짧은 수명의 세션으로 바꾸는 흐름을 넣습니다. → [02-ingest](../design/02-ingest.md), [07-auth-scope](../design/07-auth-scope.md)

### 연결 실패 처리가 필수다

집 서버는 밖에서 자주 접속이 안 됩니다(Tailscale 꺼짐 등). WebView가 빈 흰 화면을 띄우면 사용자는 앱이 고장 났다고 생각합니다. **전용 안내 화면 + 재시도 버튼**을 반드시 넣습니다.

이때 "결제 내역은 계속 저장되고 있습니다"를 함께 안내합니다. 화면이 안 보이는 것과 수집이 멈추는 것은 별개인데, 사용자는 구분하지 못합니다.

### WebView 보안 설정

```kotlin
allowFileAccess = false
allowContentAccess = false
```
서버 호스트가 아닌 URL은 WebView 안에서 열지 않고 시스템 브라우저로 넘깁니다.

## 후퇴 경로

WebView 연동이 예상보다 문제를 일으키면(쿠키 정책 변경, 특정 기종 렌더링 이슈 등) **대안 B로 후퇴**할 수 있습니다. 서버 UI가 이미 브라우저에서 동작하므로, 앱에서 WebView 탭을 제거하고 가족에게 PWA 홈화면 추가를 안내하면 끝입니다. 서버 쪽 변경은 필요 없습니다.

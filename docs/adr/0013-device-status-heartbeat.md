# ADR 0013 — 원문과 분리한 기기 상태 신호

- 상태: 채택
- 날짜: 2026-09-25

## 문제

원문이 없으면 업로드 작업은 HTTP를 보내지 않아 Device.lastSeenAt만으로는 결제가
없던 기간과 수집기 중단을 구별할 수 없다. 이 값만으로 앱이 정상이라고 보장해서도 안 된다.

## 결정

별도 15분 WorkManager가 인증된 `/api/device-status`에 엄격한 숫자/불리언 상태를 보낸다.
앱 시작/재부팅은 주기 작업을 복구한다. 본문·제목·발신자·허용 목록·예외 문자열은 보내지 않는다.
프로토콜 버전, 앱 versionCode, 대기/격리 건수, 마지막 로컬 저장·전송 시도·응답 반영,
RCS 자동 보충 선택/시도/완료 구간, 알림/SMS 권한만 최신 스냅샷으로 보관한다.

서버는 body 4KiB 상한과 필드 허용 목록을 검사하고 요청 토큰의 기기만 갱신한다.
기기 ID/구성원 ID를 클라이언트가 지정할 수 없다. 갱신 직전에도 폐기 여부를 검사한다.
수신 시각은 서버 시계로 Device.statusReportedAt에, 관찰 값은 statusSnapshot JSON에 둔다.
기존 lastSeenAt(원문 업로드 인증 시각)과 RawMessage에는 영향이 없다.

조회는 visibleMemberIds를 경유한다. 상태 미수신은 구버전/미보고로 표시한다.
6시간 이상 미수신은 '상태 확인 필요'로 표시하며 앱 중단으로 단정하지 않는다.
폰 시계·절전·네트워크·강제 종료에 따라 지연될 수 있다. 서버 도착 시각이 최신이어도
알림 권한과 큐 적체, RCS 진행 시각을 별도로 확인한다.

상태 전송 실패는 원문 업로드나 대기열을 변경하지 않는다. 재시도는 별도 WorkManager에
국한하며 설정 화면에 마지막 성공 시각을 표시한다. 기존 앱은 새 API를 몰라도 계속 수집한다.

## 검증

타인 기기 지정/추가 원문 필드/잘못된 수치/큰 본문/미인증/폐기 경합을 거부하는 테스트,
SELF/FAMILY 조회 범위와 Android의 숫자 전용 wire payload를 검증한다.
DB는 nullable 컬럼 두 개만 추가하며 최종 배포 전에 격리 복원 DB에서 migration과
기준 RawMessage 보존을 확인한다. 버전과 배포는 전체 작업 종료 후 한 번만 한다.

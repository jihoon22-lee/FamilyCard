# ADR 0025 — 수집된 알림의 자동 사용액 집계

- 상태: 채택 (2026-09-27 사용자 요청)
- 배경: 카드/파서 설정을 사용자에게 넘겨 운영 거래가 0건이었다. `04-card-matching`은
  미등록 카드도 전체 사용액에 포함하도록 정했지만 처리 구현은 모두 REVIEW로 제외했다.

## 결정

1. 실제 보관 표본에서 확인한 KB/하나/삼성/롯데 형식을 버전이 있는 기본 ParserRule로
   제공한다. 규칙과 원문 출처(source/package/origin)를 함께 확인한다. 표본 없는 카드사
   형식은 추측하지 않고 후속 원문으로 보완한다. 원문/실제 값은 Git에 넣지 않는다.
2. 금액이 확인된 카드사 거래는 카드 등록 전에도 CONFIRMED로 집계한다. `cardId=null`은
   상품 미분류일 뿐 금액 불확실을 뜻하지 않는다. 상품/결제일/마스킹 숫자를 만들어 등록하지
   않는다. 상품별 실적 추정은 기존대로 카드와 공식 조건이 있어야 한다.
3. 미등록 거래의 취소는 동일 소유자·카드사·원문 카드 토큰 안에서 기존 원거래 날짜/가맹점/
   금액/모호성 검사를 적용한다. 등록 카드와 미등록 토큰을 무조건 같은 카드로 합치지 않는다.
   취소는 원승인의 canceledAmount로 투영하며 원거래가 없는 취소는 검토 상태로 보존한다.
4. 동일 출처/본문/제목/승인시각이며 수신 간격 1초 미만인 알림 반복은 근거로 연결한다.
   그 외 같은 금액만으로 연속 결제를 합치지 않는다.
5. 토스 등 보조 알림은 별도 지출로 더하지 않는다. 같은 소유자·카드사·금액·가맹점과
   수신 2분 범위에서 카드사 거래가 유일할 때 근거를 연결한다. 후보가 복수이거나 금액만 같은 다른 가맹점이면 REVIEW를 유지한다.
   같은 승인일·가맹점·금액의 카드사 거래가 2분 밖에 있어도 지연 가능성 때문에 보조 승인을
   중복 합산하지 않고 REVIEW로 둔다. 원 승인일과 수신일 양쪽의 보조 근거를 재평가한다.
   카드사를 명시한 보조 승인만 있고 대응 가능한 카드사 알림이 전혀 없으면 미분류 사용액으로
   합산한다. 이후 카드사 알림이 오면 다시 연결하므로 두 번 더하지 않는다. 늦게 온 카드사 알림도 다시 평가하며 모호해지면 보조 연결을 해제한다.
6. 과거 원문을 격리 복원 DB에서 재처리하고 원문 해시·순액·권한·재실행을 검증한 뒤 운영
   재처리 및 자동 처리기를 켠다. APK/버전은 변경하지 않는다.

## 한계

외화 알림의 원화 확정액, 원거래가 수집되지 않은 취소, 식별 불가능한 보조 알림은
숫자를 추측하지 않는다. 계산 가능한 전체 사용액과 미해결 건수를 함께 보여준다.

# ADR 0014 — 개발 진행과 실기기 배포 검증 분리 (제안)

- 상태: 제안, 사용자 결정 대기. 기존 Phase 3 진입 제한은 아직 유효.
- 날짜: 2026-09-25

## 문제

사용자는 전체 계획의 연속 진행과 마지막 한 번의 버전 업데이트를 요청했다.
기존 AGENTS.md는 Phase 2 완주 전 Phase 3 착수를 금지하고, Phase 2에는 실기기 검증과
운영 서명 전환이 포함된다. 아직 확인 결과가 없어 개발까지 반복 정지하고 있다.

## 구체적인 제안

1. 완료된 수집 구현·실제 원문 보존·격리 복원 검증을 개발 기준선으로 삼는다.
2. S03~S09 구현은 기능 브랜치와 격리 복원 DB에서 진행한다. 실제 원문은 DB 안에서만
   분석하며 Git에는 가공 샘플만 둔다. 운영 RawMessage와 기존 수집 서비스는 유지한다.
3. 개인정보 canary·RCS·오프라인/재부팅·서명/설정 보존·가족 커버리지는 **최종 배포 전
   검증 조건**으로 남긴다. 미확인을 성공으로 표시하지 않고 Phase 2 완료도 선언하지 않는다.
4. 실기기 검증이 안 끝나면 새 기능을 운영에 배포하거나 최종 버전을 발행하지 않는다.
5. 실제 표본 없는 카드사 정규식은 추측하지 않는다. 미지원 원문 보존/미확정/재처리 경로를
   먼저 만들고 검증된 형식만 활성화한다. 실적 공식 조건/정답 없는 값은 확정하지 않는다.
6. 한 사이클 정확도·장기 자원 검증은 실제 시간이 지난 뒤 완료한다. 기능 구현 완료와
   실사용 완료를 구분한다. 버전은 사용자 지시대로 최종 한 번, 브랜치는 병합마다 정리한다.

이 제안은 AGENTS.md의 Phase 2→3 개발 순서를 바꾸므로 사용자 결정 전에는 적용하지 않는다.
승인되면 AGENTS.md/실행 계획의 해당 순서에 이번 작업의 예외를 명시하고, 미완료 배포 검증은
수집 검증표에 계속 유지한다. 원문 보존·개인정보 경계·권한·netAmount 불변 규칙은 바꾸지 않는다.

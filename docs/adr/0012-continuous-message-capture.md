# ADR 0012 — RCS 자동 보충과 새로운 문자 형식 보관

- 상태: 채택
- 일자: 2026-09-24
- 근거: 사용자가 앞으로 추가될 카드·출처·문구의 지속 수집과 후속 재처리 계획을 승인
- 관련: [ADR 0010](0010-sms-history-import.md), [ADR 0011](0011-samsung-rcs-history.md)

## 배경

수동 RCS 가져오기만으로는 앞으로 도착할 취소를 지속해서 확보하지 못합니다. 또 기존
거래 어휘 목록에 없는 SMS/RCS는 등록 발신자라도 저장되지 않아 후속 파서가 복구할 원문이
없습니다. 반면 등록 발신자의 모든 문구를 보관하면 광고·인증번호도 포함될 수 있습니다.

## 결정

두 설정을 별도로 제공하며 모두 기본값은 꺼짐입니다. 업데이트·기존 READ_SMS 권한·
기존 수동 가져오기 이력을 근거로 자동 활성화하지 않습니다.

### 삼성 RCS 자동 보충

- 사용자가 켤 때 READ_SMS 권한과 문자 발신자 등록을 확인하고, 기존 삼성 시스템 provider
  호환 경로를 사용합니다. 수신 RCS만 대상이며 SMS/MMS/카카오 보관함을 자동 조회하지 않습니다.
- 15분 주기 WorkManager와 사용자의 즉시 확인 작업을 사용합니다. OS 절전 정책에 따라
  지연될 수 있어 실시간 또는 정확한 15분 간격을 보장하지 않습니다.
- 로컬 읽기에는 네트워크 제약을 두지 않습니다. 큐 저장과 서버 업로드는 분리합니다.
- 켠 시점의 최근 하루부터 시작합니다. 성공한 조회 종료 시각을 기록하고, 후속 실행은
  하루를 겹쳐 읽습니다. 장기 중단 구간은 최대 7일씩 순차 조회·완료 기록합니다.
- 본문·큐 오류, 미지원·권한 거부, 작업 취소에서는 해당 구간의 진행 시각을 전진시키지
  않습니다. 폰 시계가 뒤로 이동하면 기존 진행 시각을 유지하고 상태를 표시합니다.
- 끄기/재활성화마다 작업 세대를 바꿔 이전 작업이 새 설정의 큐 저장·진행 시각을 갱신하지
  못하게 합니다. 재부팅·앱 시작은 사용자가 켠 주기 작업만 복구합니다.
- 매 실행 시작 시 등록 발신자를 고정하고, 본문 조회 전과 저장 전에 현재 허용 목록도
  확인합니다. 실행 도중 추가된 발신자로 범위를 넓히지 않습니다.
- 수동 가져오기와 같은 사건 ID를 사용합니다. 겹쳐 읽은 원문은 재전송될 수 있지만
  서버의 `(deviceId, clientMessageId)` 제약으로 중복 저장하지 않습니다.
- 본문 전체 목록을 메모리에 만들지 않습니다. 상태에는 건수·시각·고정 문구만 저장하고
  본문·발신자·예외 문자열은 넣지 않습니다. 크기 제외 경고는 후속 성공에도 유지합니다.

### 등록 문자 발신자의 모든 문구 보관

- 별도 확인창에서 광고·인증번호 포함 가능성과 영구 원문 보존을 설명한 뒤 켭니다.
- 켠 경우 실시간 SMS·수동 SMS/RCS·자동 RCS의 거래 어휘 필터를 해제합니다. 빈 본문,
  권한·발신자·수신 종류·선택 기간·크기 경계는 유지합니다.
- 새 문구를 거래로 판정하거나 카드에 연결하지 않습니다. 서버에는 계속 원문/PENDING으로
  보존하며 후속 Phase 3의 파싱·미확정·재처리 경로가 담당합니다.
- 수동 작업에는 시작 시 선택을 고정하고 현재 선택도 재확인합니다. 진행 중 끄기는 반영하되
  켜기로 기존 작업 범위를 확장하지 않습니다. 자동 작업은 매 실행 시 선택을 고정합니다.
- 꺼도 이미 보관한 원문은 삭제하지 않습니다. 과거에 거래 어휘로 제외됐던 항목을 복구하려면
  모든 문구 보관을 켠 뒤 해당 기간을 수동으로 다시 가져옵니다.

## 이전 결정과의 관계

ADR 0010의 과거 SMS 가져오기는 계속 사용자 실행 전용입니다. ADR 0011의 수동 RCS 전용
범위는 사용자가 켠 자동 보충으로 확장합니다. 기존 사용자에게는 거래 어휘 필터를 유지하며,
화이트리스트 밖 원문을 저장하지 않는 불변 규칙은 변경하지 않습니다.

## 한계와 검증

- 보관함에서 하루보다 오래된 시각으로 뒤늦게 추가·수정된 항목은 자동 겹침 구간 밖일 수
  있습니다. 오래된 기간은 수동 가져오기로 보충합니다. 강제 종료 후 재개와 제조사 절전은
  실기기에서 검증해야 합니다.
- 가공 데이터로 장기 중단·부분 성공 후 실패·권한/미지원·취소·시계 역행 시 진행 기록과
  재시도 범위를 검증합니다. 모든 문구 모드에서도 미등록/삭제 발신자의 본문 비접근을 검증합니다.
- 실제 신규 RCS 도착·재부팅·네트워크 복구·재가져오기 서버 중복 방지는 실기기 게이트로 남깁니다.

# ADR 0015 — 원문 근거·처리 이력과 검토 가능한 거래

- 상태: 채택 (ADR 0014에 따른 격리 개발)
- 날짜: 2026-09-25

## 근거

현재 수집 원문은 946건, 등록 카드/거래/파싱 규칙은 0건이다. 출처는 카드사 앱 403,
결제 앱 479, 카카오 25, SMS 9, RCS 30이다. 이 건수는 거래 정답이나 의미 중복의 증명이 아니다.
RCS는 message.generalPurposeCard.content 구조 17건과 card 문자열 구조 13건을 확인했다.
본문/개인 식별 값은 출력·커밋하지 않고 JSON 필드 구조와 건수만 확인했다.

## 결정

- Transaction.rawMessageId는 기존 대표 원문의 안정적 키로 유지한다.
  새 TransactionEvidence가 모든 근거를 연결한다. 원문은 한 활성 거래의 근거가 되며,
  대표 원문도 연결 테이블에 포함한다. 기존 거래는 migration에서 같은 근거로 backfill한다.
- 재처리는 근거 링크로 기존 거래를 찾는다. 수동 수정이나 병합/분리 판단은 잠그고,
  파싱 실패만으로 이전 거래/근거를 삭제하지 않는다. MERGED 거래는 이력으로 남기고 집계에서 뺀다.
- 같은 구성원·확정 카드·종류·금액·통화와 명시적 승인 식별 근거가 맞을 때만 자동 병합한다.
  시각/가맹점/금액 유사성만 있는 후보는 REVIEW. 별도 연속 결제를 자동으로 합치지 않는다.
- 원화 금액 미확정은 amount=null이다. 해외 금액은 foreignAmount 정수와 foreignScale을
  함께 보관한다. 환산액을 0원으로 꾸미지 않으며 집계의 미확정 항목으로 표시한다.
- 날짜는 UTC로 저장하되 SECOND/MINUTE/DAY/RECEIVED 정밀도를 함께 보관한다.
  취소 발생일과 알림의 원결제일을 분리한다. 날짜만 있는 값을 정밀한 승인 시각으로 취급하지 않는다.
- 같은 끝 4자리·재발급을 허용한다. Card의 기존 자연키 유일 제약은 일반 인덱스로 바꾸고,
  카드/별칭에 유효 기간을 둔다. 여러 후보는 NEEDS_CARD로 남긴다.
- 규칙 action(PARSE/IGNORE), version과 변경 snapshot을 기록한다. 규칙 없음은 NO_RULE이며
  IGNORED가 아니다. 처리 실패 원인과 마지막 적용 버전을 원문 메타데이터로 남긴다.
- 원문별 ProcessingJob으로 지속 처리/재시도/lease와 재처리 세대를 관리한다.
  수집은 먼저 원문을 보존하고 작업 누락을 복구 가능한 스캐너가 메운다. 주기 스캔은 작은 배치다.
- 기기 없는 수동/명세서 원문은 ownerMemberId로 귀속하고 실제 기기를 만들지 않는다.
  deviceId가 있으면 항상 기기 소유자의 scope를 사용하고, 없을 때만 ownerMemberId를 사용한다.
  이전 원문의 ID/본문/출처/시각은 바꾸지 않는다.
- 명세서 원본 파일은 StatementImport에 별도 보관하고 행의 원문은 RawMessage로 연결한다.
  행 매칭·수정은 후속 구현이며 파일이 없다는 이유로 승인/취소를 임의 변경하지 않는다.
- 수정/병합/분리/수동 지정을 ReviewDecision에 구성원 범위와 함께 감사 기록한다.

## 배포와 검증

운영은 변경하지 않는다. nullable 메타데이터와 추가 테이블을 먼저 격리 복원본에서 검증한다.
기존 거래/근거·RawMessage 보존, 스키마 diff, 권한 회귀와 가공 데이터의 재처리 멱등성을 검증한다.

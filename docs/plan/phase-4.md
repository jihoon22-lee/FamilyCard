# Phase 4 — 실적 엔진

> 버전 태그: `v0.4.0`
> **이 프로젝트의 목표 지점입니다.**

## 목표

카드별 전월실적 달성 추정치와 **"N원 더 쓰면 달성"** 을 보여줍니다.

## 완료 기준

- 카드별 실적 진행률이 보임
- 제외된 건과 그 사유를 확인 가능
- **실제 카드사 앱 수치와 대조해 오차를 튜닝한 상태**
- 실적을 표시하는 모든 화면에 "추정치" 명시

## 작업

### 실적 엔진
- [ ] `src/lib/benefit/` — `CardBenefitRule` 적용, **`netAmount` 기준**
- [ ] 사이클 계산
  - `PREV_CALENDAR_MONTH` — 전월 1일~말일
  - `STATEMENT_CYCLE` — `Card.statementDay` 기준
  - **KST로 경계를 만든 뒤 UTC로 변환해 비교** ★
- [ ] 제외 항목 판정
  - 공통: `TAX` · `INSURANCE` · `GIFT_CARD` · `PREPAID` · `APT_FEE` · `TRANSIT` · `TUITION`
  - 카드별 토글: `UTILITY_GAS` · `UTILITY_ELEC` · `UTILITY_WATER` · `TELECOM` · `INTERNET`
  - 가맹점명 패턴 + 카테고리 병용
- [ ] `excludeReason`을 **거래에 저장** (UI에서 사유 설명용)
- [ ] `minPerTxAmount` 건별 최소 금액
- [ ] 취소 반영 — `cancellationPolicy` 분기
- [ ] 구간 판정 — 달성한 가장 높은 `threshold`, 다음 구간까지 남은 금액
- [ ] 미확정 건(`cardId = null`)은 자동 제외 (조회 조건상 자연스럽게)

### 화면

- [ ] 제외된 건 목록 (펼치기) — 거래별 제외 사유
- [ ] 미확정 경고 — "카드 미확정 N건이 실적에 반영되지 않았습니다"

### 실적 규칙 편집 UI

- [ ] 제외 항목 체크박스 — 공통은 기본 체크, 갈리는 항목은 사용자 선택
- [ ] 산정 기간 방식, 건별 최소 금액, 취소 차감 정책
- [ ] **프리셋 제공** — "30/70/100만원 3구간, 공과금 제외" 등. 입력 부담 축소

## 주의

### "추정치" 표기는 타협하지 않는다

사용자가 이 숫자를 카드사 공식 수치로 오인하면 **실제로 손해를 봅니다.** "달성했다"고 믿고 안 썼는데 미달이었다면 혜택을 놓치는 것이고, 그건 시스템이 아예 없는 것보다 나쁩니다.

→ [불변 규칙 6](../../AGENTS.md)

### 시간대 버그는 조용히 틀린다

★ 표시한 KST/UTC 경계는 반드시 테스트하세요. UTC 기준으로 월 경계를 비교하면 **매월 며칠만 증상이 나타나** 발견이 늦습니다. 그동안 실적이 계속 틀립니다.

### 첫 달에 정확도를 기대하지 않는다

제외 항목 기준은 카드사 약관에 다 적혀 있지 않습니다. 한두 달 실제 수치와 대조해가며 조정하는 과정을 전제로 설계했습니다. 처음에 오차가 나는 건 정상입니다.

### 제외 사유를 반드시 노출한다

실적 계산이 블랙박스면 숫자가 안 맞을 때 사용자가 원인을 찾을 방법이 없고, 규칙을 고칠 수도 없습니다. `excludeReason`을 거래에 저장하고 UI에서 펼쳐 보이게 하는 것이 튜닝의 전제 조건입니다.

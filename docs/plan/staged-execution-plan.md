# 단계별 통합 실행 계획

> 확정일: 2026-09-25 · 사용자가 전체 검토안을 문서화한 뒤 단계별 실행하도록 승인
> 첫 결과물: 취소가 반영된 카드별 월 사용금액과 미확정 수정·재처리
> 다음 결과물: 카드별 실적 달성 추정치와 가족 전체 현황

이 문서는 실행 순서·보강 작업·진행 상태의 기준입니다. 상세 설계와 Phase별 체크리스트는
[기존 통합 실행 계획](post-collection-execution.md), [로드맵](roadmap.md)을 함께 따릅니다.
기존 기능을 삭제하거나 미완료 게이트를 자동 통과시키지 않습니다.

## 현재 기준선

| 구분 | 확인한 상태 |
|---|---|
| 기반 | Phase 0/1 인증·scope·DB·CI/CD 구축, DEVICE는 항상 SELF |
| 수집 | 일반 알림 자동 전송, SMS/RCS 과거 가져오기, 부분취소 원문 도착 확인 |
| 실기기 | 현재 운영 기기 1대의 전송 대기 해소, 확인 필요 0건, 정상 연결에서 자동 전송 확인 |
| v7 | RCS 자동 보충·모든 문구 보관 옵션 구현/게시, 신규 옵션 실기기 검증 대기 |
| 서버 | standalone 전환·Prisma 재사용 수정 완료, 메모리 장기 추적 대기 |
| 거래 기능 | 파서·카드 매칭·대사·취소 반영·실적·미확정 UI 미구현 |

초기 검증은 현재 운영 기기와 대표 카드부터 진행합니다. 초기 지원 대상과 가족 확대 범위는
원문 커버리지 표에 명시합니다. 아직 없는 미래 형식은 미지원으로 표시하고 보존·미확정·
재처리 경로로 수용합니다. **Phase 2 완료 범위와 Gate C0 미확인 항목을 별도 근거 없이
축소하지 않으며, Phase 2 완료 전 파서 구현을 시작하지 않습니다.**

## 진행 원칙

- 상태는 미착수 / 진행 / 실기기 확인 대기 / 완료로 구분하고, 완료에는 테스트·PR·운영 또는
  사용자 확인 근거를 남깁니다. 코드 구현과 실기기 검증은 별개입니다.
- S01과 S02는 병행할 수 있습니다. 휴대폰의 확인을 기다리는 동안 서버 보안·백업 등
  독립적인 S02 작업은 계속 진행합니다. S03 이후는 Gate C0 통과가 선행합니다.
- 사용자 추가 지시(2026-09-25): 버전·태그·APK 업데이트는 전체 작업 종료 후 한 번만 수행합니다.
  중간 변경은 Unreleased에 누적하고, 병합 완료 브랜치와 해당 작업의 임시 워크트리는 즉시 정리합니다.
- 작업 단위마다 기능 브랜치 → PR → 필수 CI → GitHub 병합. DB 변경은 백업·격리 복원
  검증 후 배포합니다. Phase 종료 태그는 해당 완료 기준을 모두 충족한 뒤에만 발행합니다.
- 실제 원문·금융 값·토큰·키·백업은 Git에 넣지 않습니다. 테스트는 가공 표본만 사용합니다.
- RawMessage 기준 ID·본문·출처·수신 시각을 보존합니다. 지속 수집 중 추가된 원문은
  별도로 집계하며, 전후 총건수 일치만으로 보존 여부를 판단하지 않습니다.
- 모든 집계는 취소를 반영하며, 실적은 항상 추정치로 표시합니다. 권한 검증은 조회뿐 아니라
  카드 지정·원문 연결·재처리·명세서 보정·내보내기에도 적용합니다.

## 후순위지만 삭제하지 않는 작업

카드 추천·고급 차트·예산 알림·PDF·QR 등록은 첫 월 사용액 화면의 선행 조건이 아닙니다.
특히 혜택 한도 기반 카드 추천은 실제 혜택 사용액의 산정 근거를 확보한 뒤 구현합니다.
추가 금융 API, 다른 제조사 RCS, 과거 카카오/MMS 지원은 필요 사례와 접근 가능성을 확인한
별도 확장 항목입니다. 지원한다고 미리 표시하거나 임의로 수집 범위를 넓히지 않습니다.

## 첫 실행 묶음과 기록 방식

1. 이 계획서 PR 확정.
2. S01 실기기 미확인 항목을 요청하면서 S02-A 의존성 보안 수정·검증·배포 수행.
3. S02-B 현재 백업·격리 복원과 S02-C/D 상태/자원 기준선 작업.
4. S01·S02 남은 조건과 Gate C0를 확인한 뒤 S03 시작.

각 단계의 체크박스에는 실제 근거가 생겼을 때만 완료를 표시합니다. 세부 진행·PR·검증 결과와
다음 파일 경로는 [HANDOFF](../HANDOFF.md)에 기록하고, 장기 작업도 이 순서를 이어갑니다.

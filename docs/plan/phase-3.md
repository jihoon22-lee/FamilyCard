# Phase 3 — 파서 + 카드 매칭

> 버전 태그: `v0.3.0`
> **선행 조건: Phase 2 완주 — 실제 알림 원문이 며칠치 쌓여 있을 것**

## 목표

쌓인 원문을 거래로 바꾸고, **카드 한 장 단위** 월간 사용금액을 보여줍니다.

## 완료 기준

- 수집된 원문의 대부분이 `PARSED` 상태
- 카드별 이번 달 사용금액이 보임
- 미확정 큐에서 사람이 개입 가능하고, 지정하면 `CardAlias`가 학습됨
- 규칙 수정 후 재파싱이 동작하고 수동 편집분은 보존됨

## 작업

### 먼저: 원문 분석
- [ ] `/raw` 화면에서 수집된 원문을 카드사별로 분류
- [ ] 각 카드사의 변형을 목록화 — 승인 / 취소 / 할부 / 해외 / 마스킹 / 무시 대상
- [ ] **가공된 픽스처 작성** (실제 문자 복붙 금지 — [불변 규칙 7](../../AGENTS.md))

### 파서
- [ ] `src/lib/parser/` — `ParserRule` priority 순 적용, 첫 매치 채택
- [ ] `fieldMap` 변환기 — `money` · `installment` · `datetime_md` · `text` · `card_token` · `const`
- [ ] **연도 없는 날짜 처리** — `receivedAt` 기준, 미래면 -1년
- [ ] `IGNORED` 판정 규칙 (광고 · 명세서 안내 · 결제일 안내)
- [ ] `cardToken`은 **정규화하지 않고 원문 그대로** 넘김

### 카드 매칭
- [ ] `src/lib/cardmatch/` — 5단계
  1. `CardAlias` 조회
  2. 정확 일치 `(memberId, issuer, last4)`
  3. 마스킹 패턴 (`1*34` → `/^1.34$/`) — **1장일 때만 확정**
  4. `nickname` 부분일치 — 1장일 때만
  5. 실패 → `NEEDS_CARD`
- [ ] 후보 조회에 **`memberId` 조건 필수** (타인 카드가 후보에 들어가면 안 됨)
- [ ] 사람이 지정 시 `CardAlias` 자동 생성

### 취소
- [ ] 원거래 후보 조회 (같은 카드, 60일 이내, 잔여액 ≥ 취소액)
- [ ] 점수 매기기 (가맹점 일치, 금액 일치, 최근성) + 2위와의 격차 검사
- [ ] `canceledAmount` 누적 — **하나의 DB 트랜잭션으로**
- [ ] 고아 취소 → `isOrphanCancellation`
- [ ] **재파싱 시 이중 차감 방지** — `canceledAmount` 초기화 후 전체 재적용

### 미확정 큐 UI
- [ ] 파싱 실패 큐
  - 원문 표시 + 수동 입력 (`isManuallyEdited = true`)
  - **"이 문구로 규칙 만들기"** — 정규식 초안 생성
  - 저장 전 같은 issuer의 다른 실패 건에 시험 적용해 몇 건이 풀리는지 미리보기
- [ ] 카드 미확정 큐
  - 카드 선택 → `CardAlias` 생성
  - "새 카드 등록" 경로

### 재파싱
- [ ] `POST /api/reparse` — scope(ALL / ISSUER / STATUS / DATE_RANGE)
- [ ] `isManuallyEdited` 건 건너뛰기
- [ ] 파싱 실패 시 기존 `Transaction` **유지** (삭제 금지)
- [ ] `dryRun` — `wouldFix` / `wouldBreak` 미리보기
- [ ] `wouldBreak > 0`이면 UI에서 경고

### 화면
- [ ] 대시보드 — 이번 달 **카드별 사용금액 리스트**
- [ ] 카드 탭 → 거래 내역
- [ ] 미확정 건수 배지 (상단 상시 노출)
- [ ] 카드 관리 — 등록 · 수정 · 비활성화
- [ ] 파서 규칙 관리 화면

### 테스트
- [ ] 카드사별 승인 / 취소 / 할부 / 해외 파싱
- [ ] 연말연시 날짜 (12/31 결제가 1월에 업로드)
- [ ] 카드 매칭 — 정확일치 / 마스킹 단일후보 / **마스킹 2장 → `NEEDS_CARD`** / 별칭 / alias 학습
- [ ] **타인 카드가 후보에 포함되지 않음**
- [ ] 취소 — 전액 / 부분 2회 누적 / 잔여액 초과 실격 / 고아
- [ ] **재파싱 2회 → `canceledAmount`가 두 배 안 됨** ★
- [ ] 재파싱 시 수동 편집분 보존

## 주의

### 추측해서 확정하지 않는다

마스킹 매칭에서 후보가 2장이면 **아무거나 고르지 않습니다.** 엉뚱한 카드에 거래가 붙으면 두 카드의 실적이 모두 틀어지고, 사용자는 왜 틀렸는지 알 수 없습니다.

미확정 큐에 한 번 뜨는 비용이 훨씬 쌉니다.

### 재파싱 이중 차감

★ 표시한 항목은 실제로 놓치기 쉬운 버그입니다. 재파싱은 이 시스템의 핵심 기능이라 자주 돌게 되는데, 그때마다 취소가 중복 반영되면 실적이 계속 줄어듭니다. **반드시 테스트로 고정하세요.**

### 픽스처에 실제 문자를 넣지 않는다

원문을 보면서 규칙을 쓰다 보면 그대로 복사해 테스트에 붙이기 쉽습니다. 가맹점명·금액·이름·카드번호를 전부 가짜로 바꾸되, **구두점과 공백 구조는 실물 그대로** 두세요.

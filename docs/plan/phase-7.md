# Phase 7 — 실사용 검증 · 안정화

> 버전 태그: `v1.0.0`

## 목표

기능 개발이 아니라 **실사용 피드백 반영과 정확도 검증**입니다. Phase 6까지 기능은 다 만들어졌습니다. 이제 가족이 실제로 한 사이클(한 달) 이상 써보면서 나온 문제를 고치고, 실적 추정치를 카드사 앱 수치와 전 카드에 걸쳐 대조해 신뢰할 수 있는 수준으로 만듭니다.

## 완료 기준

- 가족 전원이 최소 한 사이클 이상 실사용한 피드백이 반영됨
- **전 카드**에 대해 최소 한 사이클 이상 카드사 앱 수치와 대조를 마치고 제외 규칙이 조정됨
- 백업에서 실제로 복구해 앱이 정상 동작함을 확인함
- 데이터가 몇 달 쌓인 상태에서도 대시보드 응답 시간이 허용 범위 안에 있음
- user-guide / admin-guide가 실제 사용 경험을 반영하도록 개정됨
- 미해결 이슈가 정리되고 `v1.0.0` 릴리스 노트가 작성됨

## 작업

### 실사용 피드백 반영
- [ ] 가족 구성원별로 앱 사용성 피드백 수집 (헷갈렸던 화면, 원했는데 없던 기능)
- [ ] 알림 누락 사례 수집 — 실제로 결제했는데 앱에 안 뜬 건
- [ ] 화면 오해 소지 점검 — "이게 실적 달성했다는 뜻인가 아닌가" 같은 모호함
- [ ] 수집된 피드백 중 우선순위 높은 것부터 반영

### 실적 정확도 검증 — 전 카드 확대 ★ 핵심
- [ ] **가족이 보유한 모든 카드**에 대해 최소 한 사이클(한 달) 이상 카드사 앱 수치와 대조 (Phase 4에서는 카드 1장만 대조했음)
- [ ] 카드별 오차 원인 기록 (할부 전환, 해외 환율 확정, 제외 항목 누락 등)
- [ ] `CardBenefitRule.exclusions` / `minPerTxAmount` 등 제외 규칙을 카드별로 조정
- [ ] 조정 후 다음 사이클에 오차가 줄었는지 재확인

### 파서 규칙 보강
- [ ] 운영 중 새로 나타난 알림 문구 변형 수집 및 규칙 추가
- [ ] 미확정 큐(`NEEDS_*`) 잔량 추이 확인 — 줄어드는 방향인지
- [ ] 잔량이 안 줄어드는 케이스는 근본 원인 분석 (새 카드 발급, 카드사 알림 포맷 변경 등)

### 백업 복구 리허설 ★ 실제로 수행
- [ ] Phase 6에서 만든 복구 절차대로 **실제 운영 백업**을 별도 환경에 복원
- [ ] 복원된 DB로 앱을 띄워 로그인·대시보드·실적 표시가 정상인지 확인
- [ ] 리허설 중 발견한 절차 문서의 오류·누락을 `admin-guide.md`에 반영
- [ ] 소요 시간 기록 (실제 장애 시 복구 시간 추정 근거)

### 성능 — 데이터 누적 이후
- [ ] 데이터가 몇 달 쌓인 상태에서 대시보드 응답 시간 측정
- [ ] 느려진 쿼리가 있으면 인덱스·집계 방식 점검
- [ ] 카드/거래 건수가 늘어난 계정 기준으로 재측정

### 문서 최종화
- [ ] `user-guide.md` — 실제 사용 경험에서 나온 질문·혼동을 반영해 개정
- [ ] `admin-guide.md` — 복구 리허설·운영 중 겪은 문제를 반영해 개정
- [ ] 미해결 이슈 목록 정리 (해결 안 됐지만 v1.0.0을 막지 않는 것들)
- [ ] `v1.0.0` 릴리스 노트 작성

## 주의

### v1.0.0은 "기능이 다 됐다"가 아니라 "숫자를 믿을 수 있다"는 뜻이다

Phase 6까지 끝나면 기능적으로는 완성입니다. 그런데 이 시스템이 보여주는 실적 달성률은 **추정치**입니다. 추정치는 실제로 한 사이클 이상 돌려서 카드사 앱 수치와 맞춰보기 전까지는 신뢰도를 알 수 없습니다. "동작한다"와 "믿을 수 있다" 사이에는 실사용 검증 구간이 반드시 필요하고, `v1.0.0`은 그 구간을 통과했다는 의미로 씁니다.

그래서 Phase 7은 새 기능을 넣는 단계가 아니라 **이미 만든 걸 실측하고 다듬는** 단계입니다. 여기서 새 기능 요청이 나오면 v1.0.0 이후 백로그로 미루고, 이 Phase의 목적(정확도·안정성 검증)에 집중하세요.

### 전 카드 대조가 필요한 이유

Phase 4에서는 카드 1장으로만 검증했습니다. 카드사마다 알림 문구·환율 확정 시점·제외 항목 기준이 다르기 때문에, 한 카드에서 잘 맞았다고 나머지 카드도 맞는다는 보장이 없습니다. 가족이 보유한 카드 전부를 최소 한 사이클씩 돌려봐야 "이 시스템의 숫자는 대체로 믿을 만하다"고 말할 수 있습니다.

### 복구 리허설은 진짜 데이터로

Phase 6에서 절차를 문서화했더라도, 그 절차가 실제 운영 데이터 규모·환경에서도 동작하는지는 따로 확인해야 합니다. 여기서는 실제로 쌓인 백업을 가지고 복원해보고, 걸린 시간과 막힌 부분을 기록하세요.

# 2026-09-25 개발·격리 검증 결과

[승인된 ADR 0014](../adr/0014-development-and-release-gates.md)에 따라 운영 수집과 분리해
구현·검증했습니다. **실기기 조건·실제 카드 정답 대조·한 사이클 실사용의 완료 기록은 아닙니다.**

## 구현한 범위

- 보존형 거래 근거·규칙 버전·지속 처리/재처리, 보수적 카드 매칭·복수 출처/취소 대사.
- 카드·별칭·미확정 검토·수동 입력/병합/분리·KST 월 사용액·상시 확인 필요 메뉴.
- 공식 조건 입력 기반 실적 추정치, 규칙/결제일 이력·제외/취소 정책·수동 분류와 기록.
- 가족/구성원 분석·13개월 비교·예산·XLSX/PDF, 명세서 원본/행 보존과 검토 후 보정.
- 수집 상태·실적 변화 알림, 선택 웹 푸시(일반 안내만), 로컬 백업·선택 외부 보존 준비.

## 원문과 RCS

새 운영 백업의 기준 원문 **955건**을 별도 DB에 복원하고 migration **10개**를 적용했습니다.
기준 ID/본문/출처/수신 시각 등 불변 필드의 해시 비교에서 누락 0·변경 0입니다.
이 작업의 복원/마이그레이션 검증은 약 **3초**였습니다. OS 재설치·이미지 다운로드·실기기
재연결 시간은 포함하지 않습니다. 이전 실제 dump와 복원 DB도 보존했습니다.

[값 없는 형식 인벤토리](raw-format-inventory-2026-09-25.md)는 955건의 출처/키워드 집계이며
거래 정답셋이 아닙니다. legacy RCS 13건은 `card` 값 대신 `LinearLayout/TextView.text`에
취소 본문이 있었습니다. 버튼·이미지·동작 노드를 제외하는 제한된 추출을 추가했습니다.
실제 부분취소 원문 1건은 값을 출력하거나 운영 규칙으로 저장하지 않고 메모리에서 파싱 성공을
확인했습니다. 화면의 줄바꿈이 실제 문자열에서는 공백이므로 가공 회귀 샘플도 이를 반영했습니다.

## 회귀와 배포 산출물

- Web 전체 **241 tests**: 격리 DB 포함. 실제 값은 테스트/커밋에 사용하지 않음.
- Android **102 tests**, `lintDebug`, debug APK/메타데이터 빌드 성공. 게시하지 않음.
- Python **23 tests**: 백업/복구 사전 검사·보존 정책·GPG 왕복·감시·업데이트 사전 검사.
- Web typecheck/lint/format, 의존성 감사(알려진 취약점 0), standalone 빌드.
- 후보의 실제 DEVICE 세션으로 원문/거래/실적/분석/명세서/알림·보고서·원본 다운로드,
  타인 데이터/파일/위조 memberId 거부와 Server Action 본인/타인 쓰기 경계를 검증.
- PDFKit의 동적 폰트 추적에 pnpm 실제 패키지 경로를 사용하도록 수정했습니다. symlink
  경로에 파일을 복사해 패키지 디렉터리를 가리는 회귀를 CI standalone PDF/XLSX 생성으로 검사합니다.
- PDF 3쪽을 렌더링해 한글·마지막 행을 확인했고, 엑셀 10,000행/PDF 2,000행 한도 생성도
  V8 old-space 256MiB에서 성공했습니다(가공 표본, 해당 단독 검사 RSS 약 315MiB).

## 누적 데이터 성능과 메모리

운영 백업을 복원한 격리 DB에 **13개월치 가공 승인 5,000건 + 취소 500건**을 보존 생성했습니다.
같은 후보 컨테이너에서 각 경로 3회, 추가 조회 40회와 PDF 5회(측정 요청 총 63회)를 순차 실행했습니다.
운영 서버/DB에는 가공 거래를 넣지 않았습니다.

| 경로 | 최초 | 이어진 두 요청 |
|---|---:|---:|
| 대시보드 | 166ms | 44~64ms |
| 거래 목록 | 102ms | 83~88ms |
| 분석 | 106ms | 71~82ms |
| 실적 추정치 | 95ms | 86~100ms |
| 엑셀 | 144ms | 78~81ms |
| PDF | 508ms | 413~414ms |

실적 계산은 전체 장부 대신 산정 기간과 필요한 연결 원거래만 조회합니다. 날짜 포맷터를 재사용하고
운영 이미지 V8 old-space를 256MiB, web 컨테이너 기본 상한을 512MiB로 두었습니다.
추가 반복 조회 중 측정 메모리는 **164~165MiB**, PDF 반복까지 포함한 최대 관측치는 **218MiB**였습니다.
샘플링 사이의 순간 최고치를 증명하는 값은 아닙니다. 후보를 재시작한 뒤 세션/화면과 가공 원문
5,500건·기준 실제 원문 955건의 보존을 확인했습니다.

이 수치는 로컬 환경의 단기·가공 부하 검증입니다. 폰 네트워크 지연, 모든 카드사의 실제 데이터,
한 달 메모리 누수를 검증한 결과는 아닙니다. 현재 운영 수집 서버는 별도 3시간여 관찰 15개 표본에서
약 **87~94MiB**였고 마지막 오류/경고는 없었습니다. 최종 후보 기능은 아직 운영에 배포하지 않았습니다.
자원 경고는 새 512MiB 예산에 앞서 **384MiB**부터 표시하도록 조정했습니다.

## 남은 실제 조건과 버전

- [수집 실기기 검증표](../plan/collection-validation.md)의 개인정보 canary, RCS/권한/오프라인/재부팅,
  수집 대상 삭제·가족 확대/지원 범위 확인.
- 실제 카드 등록과 거래 정답 묶음, 검토된 카드사 규칙/실적 약관, 실제 명세서·한 사이클 대조.
  알려진 오매칭/오병합 0·자동 처리율 95%는 아직 실제 정답셋으로 평가하지 않았습니다.
- 운영 서명키 전환과 암호화 이중 백업 위치, 독립 DB 백업 목적지/복원·푸시 실수신.
  로컬 private 키는 준비했지만 임의의 외부 저장소로 전송하지 않았습니다. 보존 삭제도 꺼져 있습니다.
- 현재 게시 APK는 **code 7 / 0.2.0**, 서버 package는 **0.1.0**, 기존 Git 태그는 **v0.1.0**입니다.
  후보 APK는 같은 패키지/인증서이나 code 7이므로 사전 검사에서 `version_code_not_increased`가
  나오는 것이 정상입니다. 버전·태그·게시 APK를 중간 갱신하지 않았습니다.

위 실기기 조건이 끝나기 전 새 기능 운영 배포/최종 버전 발행은 하지 않는다는 승인 결정을 유지합니다.
조건 확인 뒤 [한 번 업데이트 절차](../guide/safe-final-update.md)로 버전과 문서·산출물을 함께 갱신합니다.
